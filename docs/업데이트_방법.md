# 플레이하며 공략집 업데이트하기

처음 배포한 뒤에는 블로그 링크를 바꾸지 않습니다. 공략집 주소는 유지하고, GitHub의 main 브랜치에 수정 내용을 반영하면 웹페이지와 오프라인 다운로드판이 함께 갱신됩니다.

## 가장 편한 방법

이 채팅에 아래 내용을 알려주세요. 캐릭터명과 병과명은 게임 화면에 보이는 그대로 보내면 됩니다.

```text
부: 3부
구간/맵:
난이도와 게임 버전:
캐릭터:
현재 직업·장비:
실제로 확인한 점:
기존 공략과 달랐던 점:
공략 본문을 바꿀지, 개인 플레이 기록으로 남길지:
```

개인 플레이의 한 사례는 곧바로 보편적인 사실로 확정하지 않습니다. 개인 기록, 추가 확인 필요, 확인됨 상태를 구분합니다. 다른 난이도·패치에서 동일하다는 근거가 없으면 그 범위를 적습니다.

## 수정 위치

| 수정 대상 | 파일 |
| --- | --- |
| 3부 캐릭터 평가·세팅·맵 역할 | data/part3/characters.json |
| 1부 캐릭터 상세·루트별 중복 카드 원본 | data/part1/characters.json |
| 1부 재배·포획·진행·전직·특수 기능 | content/part1/ 안의 해당 HTML |
| 3부 구간별 맵 공략 | content/part3/p3-map.html |
| 3부 재배·군단·포획·칼날 울림·공연 | content/part3/p3-special.html |
| 출처 링크·최근 확인일·자료 상태 | data/sources.json |
| 전체 버전·최종 수정일·게임 패치 버전 | data/site.json |
| 독자에게 표시할 변경 기록 | data/changelog.json |
| 1부 / 3부 초상화 | assets/part1/ / assets/part3/ |

1부의 같은 캐릭터가 전체 도감과 여러 루트에 반복되어도 캐릭터 파일은 한 번만 수정합니다. 빌드할 때 모든 해당 카드에 반영합니다. 1부와 3부는 같은 캐릭터라도 서로 다른 데이터를 사용합니다.

## 3부 캐릭터 수정

characters.json에서 name이나 id로 대상을 찾습니다. id는 인물의 고정 키이므로 바꾸지 마세요.

- evaluation: 캐릭터 평가
- setup: 장비·세팅
- mapTip: 맵에서 맡길 역할
- jobs: 추천 직업과 요구 조건
- core: 핵심 후보 여부
- sourceRank: 원문 종합 등급. 직접 플레이한 느낌만으로 출처의 등급을 변경하지 마세요.
- verification: 확인 범위와 남은 불확실성
- sources: data/sources.json에 있는 출처 ID
- updatedAt: 해당 캐릭터의 마지막 실제 수정일
- observations: 날짜·구간·난이도를 붙인 플레이 기록

플레이 기록 형식은 다음과 같습니다. 아래는 작성 형식이며 실제 검증 결과로 게시되어 있지 않습니다.

```json
{
  "date": "2026-11-05",
  "chapter": "실제 진행한 구간과 맵",
  "difficulty": "실제 난이도",
  "status": "personal",
  "text": "현재 직업·장비에서 직접 확인한 내용"
}
```

status는 personal(개인 플레이), pending(추가 확인 필요), confirmed(확인됨) 중 하나입니다. confirmed로 바꾸려면 verification과 출처·검증 조건도 함께 갱신하세요.

1부 상세는 기존 디자인을 유지하기 위해 detailHtml에 보존되어 있습니다. 1부 내용을 크게 고칠 때는 이 채팅에서 요청하는 편이 편합니다. 보존된 초상화·직업표·역할을 함께 확인해 수정합니다.

## 한 번의 업데이트 순서

1. 해당 부·캐릭터·맵 파일을 수정합니다.
2. 필요한 출처와 검증 상태, 캐릭터 updatedAt을 갱신합니다.
3. data/site.json의 version과 updatedAt을 갱신합니다. 게임 패치를 확인했으면 gameVersion에도 적습니다. 모르면 null을 유지합니다.
4. data/changelog.json 맨 위에 날짜·버전·대상 부·변경 요약을 추가합니다.
5. 로컬에서 node scripts/build.mjs로 검사하거나, GitHub 브랜치에 올려 Actions 검사를 확인합니다.
6. main에 반영되면 GitHub Pages 배포가 실행됩니다. 실패 시 새 버전은 배포되지 않으며 마지막 성공 버전이 유지됩니다.

3부 초상화는 외형이 바뀐 인물의 전용 컷을 우선 사용합니다. 외형 불변 목록에 있는 인물은 portraitKind를 unchanged로 지정하고 portraitSource에 확인한 원본 URL을 기록하면 기본 초상화를 사용할 수 있습니다. 1부 이미지를 참조할 때는 같은 캐릭터 ID의 이미지여야 합니다. 외형 변화가 미확인인 인물을 임의로 동일 처리하지 마세요.

수정할 내용이 여러 파일이면 브랜치에서 함께 작업한 뒤 한 번에 main에 반영하면 중간 상태가 노출되지 않습니다. JSON 문법 오류·중복 인물 ID·부가 다른 이미지·없는 출처 ID는 빌드에서 차단합니다. 게임 정보 자체의 진위는 자동 판정하지 않습니다.

## 직접 실행하기

Node.js 22 이상이 필요하며 추가 패키지 설치는 없습니다.

```sh
node scripts/build.mjs
node scripts/serve.mjs
```

브라우저에서 http://127.0.0.1:4173 을 엽니다. 배포용 산출물은 dist/에 생성됩니다. dist/를 직접 수정하지 말고 data/와 content/를 수정합니다.

## 공개 내용과 개인 진행 상태

data/의 플레이 관찰 기록은 배포되면 누구나 볼 수 있는 공략집 내용입니다. 브라우저의 진행 체크리스트는 각 방문자의 기기에 따로 저장되며 GitHub로 전송되지 않습니다. 기기·계정 간 자동 동기화는 없습니다. 사이트에서 직접 GitHub 저장소를 수정하는 관리자 화면은 포함하지 않았습니다.

기존 체크리스트 저장 키는 유지했습니다. 다만 다운로드 파일로 보던 체크 상태가 새 github.io 주소로 자동 이동하지는 않습니다. 항목 순서를 바꾸면 숫자 인덱스로 저장된 체크가 달라질 수 있으므로, 기존 체크 항목은 순서를 유지하고 맨 뒤에 추가하는 방식을 권장합니다.

## GitHub Pages 설정

새 저장소에 이 소스를 올린 뒤 Settings → Pages → Build and deployment → Source를 GitHub Actions로 선택합니다. .github/workflows/pages.yml이 검사·온라인/오프라인 파일 생성·배포를 담당합니다.

GitHub 공식 문서: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages


## 3부 탈것·복구·부대 편성 업데이트

`data/part3/field-guide.json`에서 개별 내용을 관리합니다.

- mounts: 탈것의 출현지·먹이·계열 아이콘
- matches: 캐릭터·병과·탈것 매칭. classJa는 classes.json의 일본어 고정 키
- restoration: 지역별 재료. 수량이 상충하면 큰 값을 준비량으로 사용하고 note에 차이를 남김
- materials: 재료별 탐색·희귀 재배·복구 후 판매 기록과 아이콘
- scenarios: 2·3·4부대안. members·leader는 3부 characters.json의 인물 ID

부대원은 한 안에서 중복할 수 없고 부대당 최대 8명입니다. 빌드에서 인물 ID·탑승 병과 아이콘·재료·이미지 경로를 검사합니다. 게임 화면에서 한국어명이나 실제 요구량을 확인하면 label·note를 함께 고치세요.

게임 아이콘 출처와 분류는 `data/field-assets.json`, 이미지 파일은 `assets/field/`에 있습니다. 같은 계열의 아이콘을 종별 외형 사진으로 표시하지 않습니다. 새 아이콘도 오프라인 저장본에 함께 들어갑니다.


## 한국어 명칭 갱신

`data/korean-names.json`에서 일본어 원문 키에 대응하는 한국어명·출처·이전 이름을 관리합니다. `game-capture-reference`는 한국어 도감이 게임 화면 근거를 명시한 이름, `player-record`는 국내 플레이 기록, `pending`은 한국판명 확인 전입니다. 참고 자료가 임시 표기로 분류한 이름을 확정 상태로 올리지 않습니다. 명칭을 고쳐도 일본어 키와 지역 ID·수량·획득 조건은 바꾸지 마세요. aliases에 이전 이름을 남기면 재료 검색을 유지할 수 있습니다.
